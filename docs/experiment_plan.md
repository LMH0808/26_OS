# 正式实验方法（王晶莹）

本文件说明四类负载、种子与策略的设定、指标口径、人工核算和产物结构。
结果与结论见 [wang_jingying_report.md](wang_jingying_report.md)；指标定义以
[experiments.md](experiments.md) 为准，本文件不重复定义，只说明本次实验怎么用。

## 1. 目的

在统一观察窗口 H=200 下回答三个问题：

1. 桌面服务在**普通负载**下能否全部按期完成，基线是否稳定；
2. **台面拥堵**时先完成还是先按期：完成率与按时率如何取舍；
3. **紧急密集**与**故障强度**下，动态重排与抢占对紧急任务是否有实际收益。

死锁三项机制不在本实验范围内：这四类业务负载不人为制造循环等待，
死锁避免/检测/恢复由 `docs/experiments.md` 的固定死锁对照验证。

## 2. 负载设计

| 负载 | 构造 | 任务数 | 到达窗口 | 特点 |
|---|---|---|---:|---|
| 普通负载 `normal` | 10 次送水（约 15% 紧急）+ 5 次台面整理 + 3 次回收 | 18 | 0–110 | 基线常态，4 类资源均有竞争 |
| 台面拥堵 `crowded` | 30 次长时间台面整理 + 10 次送水 + 8 次回收 | 48 | 0–120 | 只靠单实例茶歇台排队，H 末必然积压 |
| 紧急密集 `urgent` | 8 次紧急送水 + 6 次普通送水 + 4 次整理 + 2 次回收，另有 2 个紧急插队事件 | 22 | 0–130 | 紧急截止很紧（松弛 1–3 tick），检验抢占 |
| 故障强度 `fault` | 普通负载 + 6 个环境/故障事件（茶歇台、通道、取杯区轮流不可用 6–14 tick） | 18 | 0–140 | 检验故障期间的等待与恢复 |

- 送水任务分两阶段：取杯（占 `cup_station`）→ 通道配送（占 `corridor`），可被抢占；
- 回收任务分三阶段：前往台面 → 台面收集（不可抢占）→ 原子转移到回收区；
- 整理任务独占 `tea_table`；`request_board` 为共享只读资源，不构成竞争；
- 每类负载独立取种子：`random.Random(seed * 1009 + 类别序号)`，同一 (负载, 种子)
  永远得到同一份输入，五种策略复用该输入（`workload_sha256` 相同）。

## 3. 种子与策略

- 独立种子：1–20，共 20 个；
- 策略（与固定演示同一套配置切换）：`baseline`、`fcfs`、`no_dynamic`、
  `non_preemptive`、`no_deadlock`；
- 规模：4 类负载 × 20 种子 × 5 策略 = **400 次运行**，本机约 60–70 秒。

`no_deadlock` 只作为保护组合对照。业务负载没有形成循环等待时，它主要体现
“银行家拒绝消失”的差别，不能据此断言关闭保护更优。

## 4. 指标与统计

- 指标全部取自引擎 `metrics`，口径见 [experiments.md](experiments.md)；
- 汇总用样本均值与样本标准差（n−1），`n` 为有效样本数；
- 无到达/无完成/无到期紧急任务时该指标为空，**不填 0**，汇总时从均值中剔除；
- 逐样本明细保留 `source_sha256`、`input_sha256`、`workload_sha256`，便于追溯
  代码版本、输入与负载。

## 5. 人工核算（先小后大）

正式实验前先用手算样例校验引擎指标：三条任务、H=10，执行区间可完全手推。
`python3 experiments/handcheck.py` 输出：

| 指标 | 手算 | 引擎 |
|---|---:|---:|
| 完成率 | 1.0 | 1.0 |
| 按时完成率 | 1.0 | 1.0 |
| 平均完成时延 | 2.6667 | 2.6667 |
| 平均逾期 | 0.0 | 0.0 |
| 冲突次数 | 1 | 1 |
| tea_table 利用率 | 0.3 | 0.3 |
| corridor 利用率 | 0.3 | 0.3 |

样例通过后才运行批量实验；若手算与引擎不一致，按流程先修指标或输入，不出报告。

## 6. 运行与产物

```bash
# 1) 人工核算样例
python3 experiments/handcheck.py

# 2) 正式实验（400 次）
python3 experiments/run_experiments.py --seeds 20

# 3) 汇总与图表
python3 experiments/summarize.py
```

| 产物 | 说明 |
|---|---|
| `experiments/results/inputs/<负载>_<种子>.json` | 实际输入（schema_version=1，可再次 `--input` 运行） |
| `experiments/results/raw/<负载>.json` | 该负载全部策略的指标、未完成任务与溯源字段 |
| `experiments/results/metrics.csv` | 逐样本明细，Excel 可直接打开 |
| `experiments/results/summary.csv` / `summary.json` | 按 (负载, 策略) 的均值/标准差/样本数 |
| `experiments/figures/*.svg` | 完成率、平均时延、紧急错失率、冲突次数四张图 |

## 7. 已知限制

1. H 固定为 200，负载未按真实茶歇服务时长校准，结论限于“相对比较”；
2. 四类负载的规模不同（18–48 个任务），**跨负载不能直接比较均值**，只能在同类负载内比较策略；
3. 业务负载不制造循环等待，`deadlock_count` 恒为 0，死锁结论须引用专项对照；
4. 单机、单线程、离散时间模型，不含人员数量约束（`workers=None`）。
